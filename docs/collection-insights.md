# 采集与数据质量

## 数据来源与请求预算

RSS 默认每 30 秒抓取一次，使用非重叠调度及失败退避；自定义间隔保存在数据库。主分支不再抓取论坛列表或详情页，不再进行数字作者 ID 补全，不需要 Python 或浏览器。旧热榜实现保存在 [独立分支](hot-ranking.md)。采集器收集的 ID 随退役迁移清理，未确认的作者显示普通名称。

## 帖子变更与订阅

同一论坛帖子以 `post_id` 识别。重复 RSS 条目只处理一次；标题、摘要、分类和作者与当前记录比较，有实际变化时仅更新当前内容，不保存旧版本。首次收录时间及原发布时间保持不变。无效或超过当前时间 5 分钟的 RSS 发布时间不替换为当前时间，该条目计入无效数据。

订阅仍使用既有精准规则，包括多关键词同时命中、显式正则、作者、分类及屏蔽词。内容同步不扩展 RSS 摘要的匹配范围，也不将详情页正文加入匹配。

| 原状态 | 内容更新后的行为 |
| --- | --- |
| 待匹配 | 保持待匹配 |
| 已匹配、待推送 | 保留队列状态，发送前仍由匹配流程复核 |
| 未命中 | 存在订阅且未删除命中时，重新进入精准匹配 |
| 已推送 | 保留成功状态、原规则关联与推送时间，不重新推送 |
| 已删除命中 | 保留移除标记，不重新展示或自动推送 |

推送入口同时检查数据库最新状态及同一进程中的在途发送，拦截已发送记录和并发重复调用。Telegram 未提供适用于该接口的客户端幂等键；上游已接收消息但响应丢失时，无法据此承诺跨网络故障的严格一次投递。

## 采集质量

RSS 配置页展示近 24 小时成功轮次、耗时及最近 30 条 RSS 采集记录。记录包含来源、时间、耗时、状态、返回与有效数量、新增与更新数量、无效条目、页数以及受控错误代码。部分 RSS 条目无效时记为“部分异常”，不丢弃本轮其余有效条目。

采集诊断最多保留 7 天且最多 10,000 条，实际保留区间同时受两项上限约束。诊断不保存代理 URL、原始异常文本、HTTP 响应正文、Cookie、令牌或密码。该接口与页面均要求有效会话。
