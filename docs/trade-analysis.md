# 交易分析

## 数据范围

独立页面 `/trades` 统计已收录且分类为 `trade` 或“交易”的帖子。默认展示全部已收录时间，支持今日、近 7 天和近 30 天。日期分桶使用浏览器时区；“今日”从该时区零点开始。未来发布时间不进入分析。

规则 v2 的首轮校准使用 2026-10-22 10:46（UTC+8）导出的全部 1,548 条公开交易帖，发布时间覆盖 2026-10-19 23:02 至 2026-10-22 10:45。分析仅使用标题、RSS 摘要、作者名称及发布时间；不读取订阅规则、命中与投递状态、账号配置或会话。校准样本包含服务器、账号、优惠码、授权与服务，并非全部属于 VPS 出售。

分析页面每 30 秒读取本地数据；页面不可见时暂停。服务端只缓存一份交易字段及解析结果，最多复用 10 秒，未变化的标题与摘要复用已有结果，不按任意搜索条件积累缓存。该功能不增加论坛网络请求，不引入外部模型服务。

## 分析维度

| 维度 | 定义与交互 |
| --- | --- |
| 发布趋势 | 按发帖日期统计出售、求购及其余意图；柱形与折线切换，支持放大 |
| 商家供求 | 归一商家名称后统计提及帖数、出售帖数和求购帖数；点击排行或选择下拉项筛选 |
| 地区 | 将香港／HKG／HK、日本／JP／东京等归入统一地区；允许每帖多个地区 |
| 商品类型 | 服务器与网络、账号、优惠与邀请码、服务与席位、软件授权、域名、通信产品、其他或未明确 |
| 报价分布 | 按币种、金额用途、付费周期分组；展示样本数、中位数、25%／75% 分位及六个等宽金额区间 |
| 规格与线路 | 明确 CPU 核数、内存单位以及 CN2 GIA、三网优化、家宽、IPLC、NAT、IPv6 Only 等文字提及 |
| 交付方式 | PUSH、改邮箱、原邮箱及中介文字提及；不判断是否可用、否定语义或费用承担 |
| 识别覆盖 | 商家、地区、求购／出售归类、金额识别及 RSS 摘要可用比例；不等同于准确率 |
| 原文依据 | 每页 20 条记录，展开查看 RSS 摘要、商家别名、金额原文与来源，原帖及已确认作者主页均在新窗口打开 |

时间、商家、地区、意图、商品类型及标题／摘要／作者搜索条件采用 AND 关系。商家和地区为多标签，一帖可进入多个商家或地区分组，因此各分组相加可能大于帖子总数。下拉选项来自当前时间范围，图表与记录采用相同筛选条件。

## 提取口径

别名词表位于 `src/config/trade-dictionary.json`，采用明确词项映射。例如“大妈”与 DMIT、“绿云”与 GreenCloud、RN 与 RackNerd 合并；不使用字符串相似度自动合并商家。提及商家可能来自对比、引用或摘要中的其他商品，不表示主体身份已经验证。

意图优先读取标题，标题无法识别时参考摘要。意图仅分为求购、出售、其他。已出、已收、已售、结帖、服务、置换、混合及无法明确判断的内容归入其他。结束标记只反映已观察文字，不表示确认成交，也不据此计算成交率或售出耗时。

金额分别保留原文、数值、币种、用途、周期及标题／摘要出处。同一帖子中数值、币种、用途及周期均相同的提及去重。可识别用途包括出售报价、周期费用、溢价、剩余价值、手续费与金额待分类。原始匹配范围采用 NFKC 规范化，并排除 URL 和邮箱，避免链接参数参与金额与实体统计。

`USD`、`CAD`、`CNY`、`EUR` 等明确标识保留对应币种。`r`、`u`、`o`、裸金额、单独的 `$`、`¥` 和“刀”不推断币种。内存、流量、IP、日期及超长数字不按普通报价解析；不将不支持的数字分隔写法截取为部分金额。

报价分布排除以下记录：多商家、多地区、结束或其他意图；币种未知；用途不属于出售报价、周期费用或溢价；周期费用未确认周期；同一组出现多个不同金额。未被排除的样本仍可能属于不同套餐或配置，也可能未识别出文本中的多商品关系。分布反映帖子报价表达，不能视为相同产品行情。样本少于 5 个时显示提示。不执行货币换算，不合计交易额，不计算成交价格。

## 权限与订阅

交易页及 `/api/stats/trades` 为公开论坛内容的只读分析，访客可访问。订阅与推送继续使用原有精准规则；分析中的别名、商品类别或金额字段不加入订阅匹配，也不写入投递队列。旧版帖子列表的 `tradeInfo` 继续使用标题提取，以保持既有接口兼容。

## 人工标记与持续改进

管理员可从每条交易帖的“标记”入口修正信息。常用区域包含商家及求购／出售／其他意图；地区、商品类型、金额、币种、金额用途与周期位于“更多字段与别名”中。意图区域仅显示求购、出售、其他，默认高亮当前结果；只有点击确认或修改的意图才记为人工字段。商家、地区留空及商品类型选择“自动识别”时不覆盖自动结果。

新增商家保存至独立商家目录，并在后续弹窗中提供最近使用和名称补全。撤销单帖标记或删除别名不会删除商家目录。商家筛选中的“未识别商家”位于选项前部并显示数量；标记成功后，记录会退出该筛选结果，便于连续处理。

单帖标记只影响对应帖子。勾选保存别名时，别名必须真实出现在该帖标题或摘要中，至少两个字符，按规范化后的文字精确匹配；英文词项限制字母边界，不执行用户输入的正则表达式。自定义别名最多 1,000 条，冲突规则必须先删除后重新保存，不能通过共享别名覆盖内置的其他商家定义。

标记保存时记录标题、摘要、人工字段及当时的规则预测。人工标签与原始帖子字段独立存储，不修改 RSS 原文、发布时间、命中、投递状态或订阅规则。标题或摘要变化后，原单帖标记暂停应用并提示待复核；管理员核对并再次保存后，标记重新生效。共享别名仍按新内容重新匹配。

“标记管理”提供共享别名删除及 JSON 导出。导出包括商家目录、当前单帖标记、共享别名和按时间记录的修改事件，供后续规则评估、标注样本核对及改进使用。撤销保留审阅记录，不自动训练模型或向外部模型服务发送数据。人工标记、目录与事件随 SQLite 数据库备份持久保存，不执行临时缓存清理。

单帖保存采用全量替换该帖人工字段的方式；恢复自动识别提交空标签对象。该操作不删除仍适用的共享别名。公开分析只返回当前生效的字段、人工来源及待复核提示；标记管理与样本导出要求有效管理员会话。
